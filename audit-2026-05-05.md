## CRITICAL — Fix before any deploy

### [C1] React development build in production
**File:** `ankitsahnimakeover (Remix)/Ankit Sahni Makeover.html`
**Problem:** Loading `react.development.js` + `react-dom.development.js` from unpkg. Dev builds are 3–5x larger, include runtime warnings, and are measurably slower. This alone will fail Google Core Web Vitals.
**Fix:** Switch to `react.production.min.js` and `react-dom.production.min.js`
```html
<!-- Replace these: -->
react@18.3.1/umd/react.development.js
react-dom@18.3.1/umd/react-dom.development.js
<!-- With: -->
react@18.3.1/umd/react.production.min.js
react-dom@18.3.1/umd/react-dom.production.min.js
```

### [C2] Babel transpiling JSX in the browser at runtime
**File:** `Ankit Sahni Makeover.html` — loading `@babel/standalone` + all JSX as `type="text/babel"`
**Problem:** Babel standalone is 1.8MB. It compiles every JSX file on page load in the user's browser. This adds 2–4 seconds to Time to Interactive on mobile. This is prototype architecture — not production.
**Fix (Phase 2):** The Next.js migration resolves this. For now, before any Vercel deploy, consider pre-compiling JSX via a build step or living with the performance hit and disclosing it.
**Impact:** LCP will be > 4s on mobile. Cannot pass Core Web Vitals. Cannot rank well.

### [C3] No sitemap.xml or robots.txt
**Location:** `ankitsahnimakeover (Remix)/` — neither file exists
**Problem:** Google cannot efficiently crawl the site. Search Console will warn. Local SEO ranking is delayed.
**Fix:** Create both files before any Vercel deploy.

### [C4] Missing image causing broken gallery item
**File:** `sec-gallery.jsx:10` — `images/8d185173-7dbc-4f02-a0c4-77ab29a14c42.webp`
**Problem:** File does not exist on disk. Gallery item "Riya · Sangeet" will show broken/fallback.

## MEDIUM — Fix within 2 weeks

### [M1] favicon.svg but no favicon.ico
**File:** `ankitsahnimakeover (Remix)/favicon.svg` exists, but HTML references `/favicon.ico`
**Problem:** SVG favicons work in modern browsers but the HTML references .ico which doesn't exist. Tab icon will be missing or show default browser globe.
**Fix:** Either convert favicon.svg to favicon.ico and add to root, or update HTML to `href="favicon.svg"`.

### [M2] CSS files have no minification — 57KB total unminified
**Files:** `styles.css` (23KB) + `refine.css` (34KB) = 57KB unminified CSS
**Problem:** For a static HTML site this is acceptable but not optimal. Phase 2 (Next.js + Tailwind) will purge unused CSS automatically. For now, 57KB is liveable.
**Track:** When migrating to Next.js, expect this to drop to < 10KB with Tailwind purge.

### [M3] Font loading blocks render
**File:** `Ankit Sahni Makeover.html` — Google Fonts loaded via standard `<link>` in `<head>`
**Problem:** Google Fonts without `font-display: swap` blocks text rendering until fonts load. No `font-display` is set in the CSS.
**Fix:** Add `&display=swap` to the Google Fonts URL (already done — confirmed in HTML). Add `font-display: swap` to any local `@font-face` declarations too.

### [M4] No `<img>` alt text strategy — accessibility and SEO gap
**File:** `parts.jsx` — Ph component renders `<img>` with `alt={label}` — this is technically present but labels like "Bridal Portrait · Hero" are not descriptive for screen readers.
