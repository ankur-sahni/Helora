# Client Rules

How client projects are started, managed, and delivered in this agency.

## Before Starting Any Client Project
- Capture baseline metrics before any automation goes live (no baseline = no case study)
- Collect all credentials and access upfront — never mid-build
- Confirm deliverables in writing (even a WhatsApp message counts)
- Create the project folder: `Projects/<client-name>/` with `CLAUDE.md`

## Onboarding Checklist
- [ ] Business brief documented in project `CLAUDE.md`
- [ ] Baseline metrics captured (current bookings, leads, response time, etc.)
- [ ] Access granted: social accounts, WhatsApp Business, Google account
- [ ] Deliverables agreed and listed
- [ ] Communication channel established (WhatsApp preferred for Indian clients)

## During the Project
- Update project `CLAUDE.md` as new information is learned
- Never deploy to a client's live account without their explicit confirmation
- Test all automations in a staging environment or with test data first
- Weekly update to client — even one line — keeps trust intact

## Handoff Standards
- Every delivered workflow must have a plain-language explanation (no jargon)
- Record a Loom walkthrough for anything the client needs to manage themselves
- Document what was built under "What's Built" in the project `CLAUDE.md`
- Leave the client with a simple one-page operations guide

## Case Study Rules
- Start capturing data from Day 1 — before and after numbers are everything
- Get a written or recorded client quote before closing the project
- Publish case study only after client approves the content
- Format: problem → system built → results (specific numbers) → client quote

## Pricing & Scope
- Every engagement has a written scope — change requests are new line items
- No unlimited-scope retainers
- Raise prices on new clients as case studies accumulate
